# People Overlay AI v3 — Windows 7 / Windows 10

**Экспериментальная версия для реальных испытаний, не стабильный релиз.**

People Overlay выделяет **фигуры людей, а не лица**, четырьмя уголками поверх
видео RVi Operator. Программа не подключается к камерам, регистратору
или сети, не модифицирует RVi. Используется изображение рабочего стола Windows.

## v3.6.2 (экспериментальная) — независимые уголки на 1–4 мониторах

- **Оригинальная v3.6 не изменена.** Данная версия разрабатывается только в ветке `feature/v3.6.2-multimonitor-offline`.
- На **каждом физическом мониторе отдельное** прозрачное кликабельное насквозь Win32 layered-окно. В отличие от v3.6.1 больше нет одного общего огромного окна для всех экранов.
- Нейросеть YOLO26n/YOLOv8n и существующие трекеры **не менялись**; отдельные захваты и трекеры на каждом мониторе уже присутствовали в v3.6.
- Отрисовка на каждом экране принимает только треки своего экрана (не переносит уголки между мониторами), правильно переводит координаты при отрицательном X/Y; тестовые уголки `Ctrl+Alt+F6` теперь показываются **по центру каждого монитора**.
- Изменение количества экранов, разрешения или порядка мониторов: Windows UI пересоздаёт HWND на главном потоке; старые результаты нейросети с недействительными координатами сбрасываются.
- `Ctrl+Alt+F5` повторно поднимает уголки **на всех экранах**, не активируя окно. Автовосстановление Z-order по-прежнему работает, но совместимость с эксклюзивными видеоповерхностями не гарантируется.
- Трей показывает количество экранов, успешно обновлённых через `UpdateLayeredWindow`. Этот показатель **не доказывает**, что RVi/SMART PSS действительно отображает слой поверх своего видеопроигрывателя.
- Пункты трея «Снимок: экран N» меняют **только целевой экран диагностического снимка**, а не детекцию. Обнаружение людей на всех подключённых мониторах до 4-х уже включено по умолчанию.
- Windows 7 **SP1** и Windows 10: отдельные автономные PE EXE для x86 и x64 с уже встроенными `model.param`, `model.bin` и совместимым `ncnnbridge.dll`. Первый запуск распаковывает их в %LOCALAPPDATA%\\PeopleOverlay (папка должна быть доступна для записи). Интернет, Python, CUDA и установка моделей не требуются; для x86 нужен процессор с SSE2.
- Автотесты: синтаксис/компиляция x64/x86 на Windows Server 2022, изоляция мониторов и отрицательные координаты, распакованные встроенные NCNN модели и детекция на контрольных изображениях. **Не считаются** испытаниями на физическом Windows 7, SMART PSS Lite, RVi Operator или четырёх мониторах.
- При симптоме «люди обнаруживаются, уголки невидимы» проверьте `Ctrl+Alt+F6` и `Ctrl+Alt+F5`, статус GDI в трее и оконный/полноэкранный режим клиента. Эксклюзивный GPU-рендеринг может блокировать обычные layered-окна: никакой Win32 TOPMOST не гарантирует отображение над ним.
- Программа — дополнение для просмотра камер, не заменяет штатную охранную сигнализацию.

## Универсальный экранный режим: RVi, SmartPSS, iVMS и другие VMS

People Overlay **не связывается с API** клиента, камер, NVR, сервером,
паролями или RTSP. Она анализирует **видимую на мониторе картинку**.
Поэтому название клиентской программы не участвует в обработке кадров.
Один EXE теоретически применим к RVi Operator / R-Operator, Dahua SmartPSS,
Hikvision iVMS, веб-страницам камер, VMS и обычному видео в плеере.

**Это архитектурная совместимость, не сертификат производителя.**
Реальные версии этих VMS не тестировались. Возможны GPU-оверлеи,
аппаратное ускорение, защищённые поверхности, несовпадение сетки с
границами монитора, системные DPI-масштабы, HDR/многомониторные конфигурации.
При этом Windows GDI BitBlt может возвращать пустой/чёрный кадр. Переключатель
CAPTUREBLT включает захват *слоистых* окон, но **не является** надёжным
резервным способом для DirectX. Desktop Duplication (DXGI) доступен с
Windows 8 и способен захватывать DirectX-рабочий стол; в **текущую
сборку ещё не встроен** и не существует для Windows 7.

**Локальная проверка без настоящей VMS:** откройте видео с людьми в
обычном полноэкранном плеере и People Overlay. В трее выберите экран
«Снимок: экран N», нажмите «Сохранить проверочный кадр» и посмотрите
файл PeopleOverlay_capture_*.png на рабочем столе. Если кадр пустой,
попробуйте вручную «Захват видео: совместимый режим (CAPTUREBLT)» и
повторите. Подпись в трее показывает яркость, процент практически
чёрных пикселей и диапазон яркостей. Почти чёрный кадр —
**предупреждение**, а не диагноз: настоящий ночной кадр также может
быть чёрным. «Проверить видеокадры» сравнивает снимки с интервалом
1,4 сек; 0% изменений не доказывает сбой, если сцена неподвижна.
Изображения никуда не отправляются. Работа с обычным видеоплеером
проверяет принцип захвата, **но не подтверждает** работу с конкретной
версией RVi или SmartPSS.

| Клиент / способ вывода | Доступен путь к изображению в текущей программе | Практически подтверждён |
| --- | --- | --- |
| RVi Operator / R-Operator | Общий экранный захват Win32 | Нет, требуется фактический клиент |
| Dahua SmartPSS / SmartPSS Lite | Общий экранный захват Win32 | Нет, зависит от рендеринга |
| Hikvision iVMS / другая VMS | Общий экранный захват Win32 | Нет, зависит от рендеринга |
| Браузер / обычный видеоплеер | Общий экранный захват Win32 | Сборка/самотест; реальная видео-сессия не проверена |

Источники по API Windows:
[Microsoft: BitBlt / CAPTUREBLT](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-bitblt),
[Microsoft: Desktop Duplication с Windows 8](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/desktop-duplication-api),
[ограничения для Windows 7](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/platform-update-for-windows-7).

## v3.5 — улучшения для Windows 11 и нескольких 4K-мониторов

- Windows 11 / Windows 10 1703+: приложение перед созданием окна запрашивает
  DPI awareness **Per Monitor v2**. Монитор с масштабом 100%, 125%, 150%
  или 200% должен использовать физические пиксельные координаты: захват
  BitBlt и угловые маркеры не должны расходиться из-за виртуализации DPI.
  На Windows 8.1 — fallback Per Monitor v1, на Windows 7 — системный DPI.
  Важное ограничение: DPI-совместимость протестирована на уровне кода и CI
  Windows Server, **физические Windows 11 с произвольными масштабами не тестировались**.
- Исправлен лимит отрисовки: раньше область из четырёх 3840x2160 дисплеев
  в ряд (15360x2160 пикселей) отклонялась из-за жёсткого лимита 10000 px.
  Теперь действует ограничение по объёму DIB в 256 MiB, а не по ширине.
- Геометрия мониторов при отрисовке опрашивается максимум раз в секунду:
  это уменьшает ненужные Win32-вызовы при частых обновлениях уголков.
  Появление/отключение монитора применяется в пределах ~1 секунды.
- Опциональный «Быстрый режим» в сетке 4x4 убирает паузы между
  нейропроверками; на старых слабых CPU оставляйте его выключенным.
- **НЕ добавлено:** Windows Graphics Capture / DXGI Desktop Duplication.
  Следовательно, совместимость GPU-рендеринга конкретных версий RVi,
  SmartPSS, iVMS всё ещё не доказана. Это улучшения существующего
  Win32 GDI захвата, а не гарантированное распознавание в любой VMS.

## Только Windows

- Целевые системы: **Windows 7 SP1 и Windows 10**, x86 и x64.
- Go 1.20.14, нативный NCNN FP32 CPU; не требуется Python, Интернет, CUDA или GPU на операторском ПК.
- Требуется совместимый CPU; для x86 — SSE2.
- Сборки создаются и проверяются на Windows Server 2022 в GitHub Actions.
  **Это не означает, что запуск на реальном Windows 7 уже протестирован**:
  нужны проверка самой Win7, драйверов, BitBlt и RVi Operator.
- Никакой поддержки иных операционных систем проект v3 не обещает.

## v3.1: авто-раскладка и приоритет точной развёрнутой камеры

По умолчанию интерфейс использует **АВТО**: экран сначала анализируется
как одна камера, а через две последовательные проверки границ RVi
при обнаружении сетки переключается в 2×2, 3×3 или 4×4. Каждый монитор
работает независимо. Действительно нестандартные или безграничные раскладки
могут распознаваться неверно — **в трее доступен ручной выбор**.

На развёрнутой камере по умолчанию включено **«Точный полный экран»**:
сокращён интервал захвата (85 мс вместо 210–300 мс) и убрана пауза
после выполненного нейровызова. В сравнении на реальных PETS2009 CCTV
с одной камерой это повысило recall **46,2 → 54,9%** в спокойной сцене
и **25,5 → 33,7%** в плотной, а задержку p95 среди распознанных
появлений в толпе сократило **4,64 → 1,85 с**.
Это всё ещё недостаточная полнота для охранной системы. Повышенная
нагрузка на CPU ожидаема — переключатель можно отключить в трее.

Когда рядом со развёрнутой камерой открыты сетки на других мониторах,
экспериментальный справедливый планировщик даёт полноэкранной камере
**3 условных доли CPU-нейросети против 1 доли у каждого сеточного экрана**.
Другие мониторы не блокируются. Временные показатели четырёх мониторов
на физических Windows 7/10 ещё не подтверждены.

Исследование дополнительных увеличенных фрагментов кадра на этом наборе
снизило recall (в толпе 15,7 → 9,2% в отдельном прогоне), поэтому
**этот вариант НЕ включён**. Встроенные веса YOLOv8n не дообучались:
оптимизировались режимы обработки кадров; нейросетевое дообучение нельзя
считать выполненным без отдельного training и независимого validation.

## v3: работа с несколькими мониторами

- Автоматически находятся до **четырёх** дисплеев Windows с разным разрешением
  и расположением, включая отрицательные координаты X/Y.
- **Все четыре монитора сканируются**, каждый с собственным кадром, очередью
  зон, трекером и номером поколения сцены.
- Прозрачный слой уголков покрывает их общий виртуальный рабочий стол;
  уголки переводятся из локальных координат в виртуальные.
- Один общий последовательный NCNN CPU worker обслуживает все мониторы,
  чтобы старый i3/i5 не получал четыре постоянно занятых нейросети.
- Проверки распределяются по дисплеям по кругу. Смена сцены на одном экране
  не сбрасывает результаты других. Отказ захвата одного экрана не должен
  блокировать проверку остальных, а старые маркеры очищаются.
- В трее пункт **«Снимок: экран N»** выбирает только экран для локальной
  диагностики, а **не** экран для детекции.
- При изменении топологии дисплеев экранные треки сбрасываются;
  устаревшие результаты AI отвергаются.

**Известные ограничения:** четырёхмониторный RVi на физическом оборудовании
не проверен. Для нескольких мониторов всё ещё используется один backend
BitBlt; режим совместимости CAPTUREBLT не гарантирует доступность любого
GPU-рендеринга RVi. Раскладки 2×2, 3×3, 4×4 и одна камера задаются через
трей, общий профиль на все экраны; нестандартные панели пока автоматически
не калибруются. 48 камер не означают 48 независимых потоков распознавания.

## Выбор модели по двум повторным CCTV-испытаниям

Один и тот же код v3 был протестирован с двумя встроенными моделями на
реальных кадрах PETS2009, имеющих ручную разметку **целой фигуры человека**.
YOLOv8n оказалась более успешной по полноте во всех четырёх сценариях двух
повторных сравнений. Во втором эксперименте на 16 камерах сетки 4×4
YOLOv8n показала **8,2% Recall** против **5,4%** YOLO26n при IoU>=0.5.
Длительность нейровычисления p95 составила примерно **252 / 258 мс**
соответственно на GitHub Windows runner. Поэтому **по умолчанию рекомендована
экспериментальная модель YOLOv8n**.

Но 8,2% Recall означает множество пропущенных людей. Это не коммерчески
готовое качество, нельзя заявлять о 2-секундной задержке на 16–48 камерах.
Измерения проведены при офлайн-воспроизведении реальных кадров, а не на
физических мониторах RVi. Метрики и происхождение роликов доступны в
[real CCTV benchmark workflow](../../actions/workflows/windows-v3-real-cctv.yml).

## Новые исследования и эксплуатационная диагностика

В Windows-трее доступно поле **«Камеры без AI-проверки»** и возраст
самой давно непроверенной камеры. Это фактическая диагностика, не обещание
распознавания человека за указанное время. При работе четырёх мониторов и
десятков камер на старом CPU возраст обычно может превышать 2 секунды.

В отдельном экспериментальном реплее две вертикально соседние камеры
объединялись в один AI-вызов. На PETS2009 с 16 потоками полнота
поднялась с **7,9 до 10,7%**, но полностью пропущенных появлений стало
больше (**54 → 59**). Поэтому **объединённые видеокамеры не включены в
рабочем режиме**; тест оставлен как исследовательский и помечен FAIL.
Второй эксперимент сравнивает свежую AI-рамку с интерполяцией старой;
только после независимого теста можно менять поведение трекера.

Отдельный [реальный CCTV quality gate](../../actions/workflows/windows-v3-real-cctv.yml)
проверяет recall, precision, полностью пропущенные появления и
95-й процентиль задержки обнаружения. Если значения не проходят порог,
CI должен показывать **ошибку качества**, даже когда сами EXE собираются.
Пробная Windows-сборка и стабильная проверенная программа — разные статусы.

## Точность и требования перед выпуском

Цель пользователя: до **двух секунд** на обнаружение новых людей,
до четырёх мониторов и 48 камер, включая неподвижных, сидящих, частично
закрытых и мелких людей. Это **цель разработки, не подтверждённый SLA**.
На слабом CPU один последовательный AI-worker физически не может
гарантировать нейропроверку всех 48 камер за 2 секунды.

Отчёт [BENCHMARK.md](BENCHMARK.md) относится к тестам **v20**, а не
к доказанному качеству v3. На реальном PETS2009 у v20 наблюдались
серьёзные пропуски; v3 не разрешено считать исправлением, пока не будет
воспроизводимого A/B теста на полностью размеченных фигурах людей.
Тесты `--selftest`, unit-tests и компиляция подтверждают только базовую
работоспособность, а не качество реальной охранной детекции.

Перед стабильным релизом нужны:
1. Проверка на реальных Windows 7 SP1 и Windows 10 с RVi и 1–4 мониторами.
2. P/R и задержки первых обнаружений по реальным body-bbox записям,
   включая отдельные отчёты для 4×4 и 48 камер.
3. Нагрузочные тесты на старых i3/i5 (CPU/RAM) и диагностика реального BitBlt.
4. Исключение регрессий по сравнению с v1.9/v20.

Программу нельзя использовать как единственное средство охранной тревоги.
