# People Overlay AI — v2.0 candidate

Портативный экранный детектор людей поверх видео RVi Operator. Четыре зелёных
уголка на человека, прозрачное для мыши окно, локальная нейросеть NCNN.
Программа не подключается к IP-камерам и не меняет RVi, регистраторы или сеть.
Python, GPU и интернет на целевом компьютере не нужны.

Это кандидат после воспроизводимых исправлений. Результаты и границы испытаний:
[BENCHMARK.md](BENCHMARK.md). Номер версии не является гарантией полевой точности.

## Запуск

1. Скачайте portable ZIP из [нового workflow](../../actions/workflows/windows-v20.yml)
   или prerelease. Распакуйте в обычную папку, закройте прежнюю копию через трей.
2. Для 64-разрядной Windows запустите `PeopleOverlay_v2.0_candidate_YOLO26n_x64.exe`;
   для 32-разрядной — вариант `x86`.
3. В RVi откройте камеры. В трее People Overlay выберите 4×4, 3×3, 2×2 либо
   «одна камера на весь экран». При переходе RVi в fullscreen переключите
   соответствующий режим People Overlay. Автоматической калибровки раскладки нет.
4. Начните с обычной чувствительности. Высокая снижает порог и увеличивает число
   кандидатов. Слабое срабатывание показывается после двух независимых
   нейропроверок; сильное — сразу. Контраст включайте при необходимости.
5. Экономный режим снижает нагрузку. Быстрое сопровождение увеличивает частоту
   захвата/вывода примерно до 15 Гц, если позволяет CPU. Это не частота нейросети
   для каждой из 16 камер.

YOLOv8n EXE содержит те же исправления приложения и другую встроенную модель.
Это ручной резерв: закройте YOLO26n и запустите подходящий YOLOv8n EXE.
Одновременно разрешена одна копия. Автоматической смены моделей в фоне нет.

## Несколько мониторов

При подключении нескольких дисплеев откройте трей People Overlay →
**«Экран 1/2/3…»** и выберите физический монитор, где открыт RVi Operator.
Экран 1 — основной монитор Windows; другие показываются с разрешением
и координатами, включая отрицательные X/Y, если монитор установлен слева.
Захват BitBlt и прозрачный слой уголков привязаны к выбранному дисплею.
При переключении монитора старые AI-результаты и треки сбрасываются.
Если выбранный монитор отключён, приложение использует основной.

**Ограничение:** пока анализируется только **один выбранный монитор за раз**.
Одновременная детекция на двух или трёх экранах потребует отдельной
очереди областей для каждого дисплея, иначе отдельные сетки 4×4
неправильно объединятся, а задержка на старом CPU значительно вырастет.
Реальный ПК с двумя мониторами разных разрешений и отрицательным
смещением в CI ещё не тестировался; проверяются Win32 геометрия,
сборка и сценарии переключения, но не полевой dual-monitor RVi.
## Управление

| Клавиши | Действие |
|---|---|
| Ctrl+Alt+F9 | Включить/выключить детекцию и очистить треки |
| Ctrl+Alt+F10 | Выход |
| Ctrl+Alt+F7 | Включить/выключить звук |
| Ctrl+Alt+F8 | Меню трея |
| Ctrl+Alt+F6 | Проверочный набор уголков |
| Ctrl+Alt+1 / 2 / 3 | Цвет маркеров |

В трее доступны чувствительность, раскладка, контраст, скорость сопровождения,
номера треков, звук, локальный снимок и диагностика захвата. Показаны времена
подготовки/нейросети/сопровождения/вывода, текущая камера, кандидаты,
подтверждённые и потерянные треки. Номер — трек этой сессии, не идентификация.

Звук: короткий сигнал по новой подтверждённой цели. Глобальная пауза по умолчанию
30 секунд (выбор 15/30/60), дополнительно 90 секунд в той же экранной зоне.
Это может заглушить нового человека в той же зоне в течение 90 секунд.
Звуковые настройки сохраняются в `%LOCALAPPDATA%\PeopleOverlay\alarm_settings.json`.

## Исправления относительно v1.9

- Ни разу не проверенные камеры стареют в очереди и получают проверку даже при
  постоянном движении в другой камере.
- Слабые кандидаты получают повторную нейропроверку и срок ожидания,
  учитывающий задержку нейросети. Неизменность фона сама не подтверждает кандидата.
- Отрицательный результат относится к положению трека на момент захвата,
  учитывается один раз и не удаляет появившегося позже человека.
- Положительный результат сохраняет время и изображение захвата; фон в момент
  завершения inference не становится эталоном человека.
- Движение фона сверяется с захваченным силуэтом. Установленные ID не сливаются
  при пересечении. Компенсация задержки сопоставляет людей взаимно однозначно.
- Декодер проверяет наибольший класс, конечность чисел и геометрию.
- Изменения настроек и быстрые переключения F9 сбрасывают сцену и отвергают
  результаты старого поколения.
- Встроенный bundle имеет приоритет над соседними файлами; кэш проверяется по
  содержимому. Упаковщик использует свежий код, донор EXE отдаёт только модель/DLL.
- `--selftest` проверяет фотографию с тремя размеченными людьми и пустой кадр.

## Что именно распознаём

**Людей целиком (класс COCO person 0), а не лица.** Программа должна
выделять фигуру человека, в том числе со спины, в капюшоне или если лицо
закрыто/неразличимо. Размер фигуры, качество записи, частичная окклюзия
и скорость обработки влияют на результат, но видимость лица не требуется.

Реальные CVAT-разметки точек лиц использовались лишь как вспомогательная
диагностика. **Наличие лица внутри рамки не подтверждает правильную
детекцию фигуры.** Для объективных precision/recall/IoU и смен ID в
реальном видео нужна покадровая разметка прямоугольников всего тела
и идентификаторов, например MOT17 с соблюдением лицензии CC BY-NC-SA.
Пока такая валидация не проведена, версия остаётся кандидатом.
## Совместимость и пределы

Go 1.20.14, сохранённые Win7 NCNN DLL x64/x86, FP32 CPU, без обязательного AVX/GPU
или внешнего VC++ runtime. Для x86 необходим CPU с SSE2. Импорты проверяются;
фактическая Windows 7 VM и древние CPU в этих испытаниях отсутствовали.

Один последовательный AI worker. Если inference занимает 300–700 мс, 16 проверок
требуют минимум 4,8–11,2 секунды без накладных расходов. Приоритет меняет очередь,
но не создаёт вычислительную мощность. Суммарные CPU-проценты могут скрывать
полностью занятое отдельное ядро.

Сетка строится от основного экрана с перекрытием crop. Произвольные панели,
смещение камер и несколько мониторов автоматически не калибруются. Визуальный
трекер ограничен текстурой, размером цели, скоростью и перекрытиями. Длительное
полное перекрытие не гарантирует сохранение ID. GPU-видео RVi может быть
недоступно BitBlt: используйте проверку двух кадров/совместимый захват из трея.

Совместимый NCNN был собран без OpenMP: прежний пункт «2 потока» не давал
реального параллелизма. Он заменён режимом более частого сопровождения.

## Воспроизведение

Go unit tests: `go test -tags ncnn ./...` на Windows, `go test ./...` на Linux.
Python используется только на сборщике.

- `scripts/package_current.py`: свежий EXE + выбранный проверенный bundle.
- `scripts/validate_native.py`: одинаковый Go FP32 tensor → NCNN против
  официального Ultralytics 8.4.78/PyTorch на bus/zidane images.
- `scripts/generate_pixel_benchmark.py`: фотографические синтетические сцены
  и геометрический ground truth, 15/30 FPS, 4×4/одна камера.
- `scripts/run_pixel_benchmarks.py`: последовательный replay и CPU/RAM процесса.
- `scripts/evaluate_pixel_benchmark.py`: P/R, пропуски, TT первого трека, ID,
  остаточные треки и поэтапные задержки.
- `scripts/build_benchmark_baseline.py`: неизменная v1.9 с тем же harness.
- `--capture-test manifest.json output-folder`: явно запрошенный визуальный
  Win32-тест отдельного окна с настоящим BitBlt, NCNN и overlay screenshot.
